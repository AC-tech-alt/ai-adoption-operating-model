# Adoption and value: the four columns

Most status reports use a single field such as "Live" or "Complete." This model replaces it with four columns, each with its own evidence.

## The columns

### Deployed
The capability exists in the system.
- Evidence: release record.
- False signal: this is where most status reports stop.

### Used
People start real tasks in it.
- Evidence: task logs, usage by team.
- False signal: logins and training attendance. A person can log in and still do the work elsewhere.

### Relied on
The old path has stopped.
- Evidence: the old report is no longer produced, the parallel spreadsheet is gone, requests go to the new path by default.
- False signal: "People like it." Liking is not reliance. Reliance means no fallback is still being maintained.

### Valued
A decision or outcome improved against the baseline.
- Evidence: shorter time to decision, less rework, more consistent handling of similar items.
- False signal: hours saved on its own. Time saved that does not change a decision is a cost reduction, not a value story.

## Example reporting view (illustrative)

| Initiative | Deployed | Used | Relied on | Valued |
|---|---|---|---|---|
| Executive reporting assistant | Yes | Partial (2 of 5 teams) | No (old report still produced) | Not yet measurable |
| Intake first-pass triage | Yes | Yes | Partial | Early signal vs. baseline |

A table like this tells leadership where to act. A single "Live" field hides it.

## Reading the pattern

- **Deployed but not used:** a readiness or placement problem. Is it inside the system people already work in?
- **Used but not relied on:** the old path was never retired. Set the date and hold it.
- **Relied on but not valued:** the work moved but the decision did not improve. Revisit the use case and the baseline.
- **Stuck for two quarters:** make a decision to fix, narrow, or stop. Do not let it drift.

## Quality sits underneath the four columns

The four columns describe adoption. They assume the output is good. Before reading any column as success, check the quality evidence from [evaluation.md](evaluation.md) and [operations-monitoring.md](operations-monitoring.md). High adoption of an unreliable tool is worse than low adoption: the organization is now relying on it.

## A note on measuring override rates

Do not set a target override rate. A low rate can mean the model is good or that reviewers have stopped checking. A high rate can mean the model is weak or that reviewers are engaged. Use the rate to ask questions, and always read it next to sampled review results.
